## 10. Подключение Logitech M185 к модулю КВВ

### 10.1. Постановка задачи

Мышь Logitech M185 — беспроводное устройство, работающее через USB-приёмник. Для подключения к модулю КВВ необходимо:

1. Передать данные от мыши к компьютеру через модуль КВВ.

3. Обеспечить двунаправленную передачу (мышь передаёт данные, компьютер может отправлять команды).

### 10.2. Анализ интерфейса USB-приёмника

USB-приёмник Logitech M185 подключается к порту USB type-A. Физически интерфейс USB состоит из 4 линий:

| Контакт | Назначение  |
| ------- | ----------- |
| 1       | VBUS (+5 В) |
| 2       | D−          |
| 3       | D+          |
| 4       | GND         |

Передача данных осуществляется дифференциальной парой D+ и D−. В состоянии покоя обе линии находятся в состоянии IDLE. Пакет данных начинается с поля SYNC, затем следует тело пакета (PACKET) и идентификатор конца пакета (EOP), после чего линии возвращаются в IDLE.

**Временная диаграмма передачи данных USB**

![image-20261001131742811](C:\Users\ThunderPC\AppData\Roaming\Typora\typora-user-images\image-20261001131742811.png)

В начале линии передачи данных (D+ и D−) находятся в состоянии бездействия (IDLE). Чтобы начать передачу пакета, сначала нужно отправить поле синхронизации (SYNC), обеспечивающее согласование между участниками передачи данных. Затем идёт само тело пакета (PACKET), которое сменяется идентификатором конца пакета (EOP), после чего линии передачи данных возвращаются в состояние бездействия (IDLE).

### 10.3. Преобразователь USB-to-LPT

Поскольку модуль КВВ работает с интерфейсом LPT (IEEE 1284), необходимо преобразовать USB-сигнал в LPT. Для этого используется преобразователь **USB to LPT converter**, поддерживающий режим **ECP (Extended Capabilities Port)**.

### 10.5. Режим ECP

При переходе на режим ECP контакты переназначаются:

| SPP Signal | ECP Mode Name   | In/Out |
| ---------- | --------------- | ------ |
| nSTROBE    | HostClk         | Out    |
| nAUTOFEED  | HostAck         | Out    |
| nSELECTIN  | 1284Active      | Out    |
| nINIT      | nReverseRequest | Out    |
| nACK       | PeriphClk       | In     |
| BUSY       | PeriphAck       | In     |
| PE         | nAckReverse     | In     |
| SELECT     | Xflag           | In     |
| nERROR     | nPeriphRequest  | In     |
| Data[8:1]  | Data[8:1]       | Bi-Di  |

**Временная диаграмма передачи данных от хоста к периферийному устройству:**

![image-20261001133027612](C:\Users\ThunderPC\AppData\Roaming\Typora\typora-user-images\image-20261001133027612.png)

**Этапы передачи:**

1. Хост помещает данные на линию данных и указывает, что передаваться будут данные, устанавливая высокий уровень HostAck.
2. Хост устанавливает низкий уровень HostClk, чтобы указать, что данные готовы.
3. Периферийное устройство подтверждает, что получило сигнал готовности, устанавливая высокий уровень PeriphAck.
4. Хост устанавливает для HostClk высокий уровень. По фронту данного импульса данные принимаются периферийным устройством.
5. Периферийное устройство устанавливает низкий уровень PeriphAck, чтобы указать, что оно готово к приёму следующего байта.
6. Цикл повторяется, но на этот раз передаваться будет команда, поскольку HostAck имеет низкий уровень.

**Временная диаграмма передачи данных от периферийного устройства к хосту:**

![image-20261001133139194](C:\Users\ThunderPC\AppData\Roaming\Typora\typora-user-images\image-20261001133139194.png)

**Этапы передачи:**

1. Хост запрашивает передачу в обратном направлении, устанавливая низкий уровень nReverseRequest.
2. Периферийное устройство сигнализирует, что можно продолжать, устанавливая низкий уровень nAckReverse.
3. Периферийное устройство помещает данные на линию данных и указывает, что передаваться будут данные, устанавливая высокий уровень PeriphAck.
4. Периферийное устройство устанавливает низкий уровень PeriphClk, указывая, что данные готовы.
5. Хост подтверждает, устанавливая высокий уровень HostAck.
6. Периферийное устройство устанавливает высокий уровень PeriphClk. По фронту данного импульса данные принимаются хостом.
7. Хост устанавливает HostAck на низкий уровень, чтобы указать, что он готов к приёму следующего байта.
8. Цикл повторяется, но на этот раз передаваться будет команда, поскольку уровень PeriphAck низкий.

### 10.6. Модуль КВВ

Модуль КВВ содержит 12 восьмиразрядных регистров цифровых входов и выходов (ЦВВ). В зависимости от коммутации управляющих входов можно выбрать различные режимы работы регистров.

**Основные обозначения:**

- **6 регистров РгА** — подключаются к каналам с нечётными номерами (КВВ1, КВВ3, …, КВВ11).
- **6 регистров РгВ** — подключаются к каналам с чётными номерами (КВВ2, КВВ4, …, КВВ12).

**Управляющие сигналы:**

| Сигнал  | Контакты модуля           |
| ------- | ------------------------- |
| «Общий» | XT2:B31; XT3:B31; XT4:B31 |
| «ТИ1»   | XT2:A2; XT4:A23           |
| «ТИ2»   | XT2:B3; XT4:B23           |
| «+5в»   | XT2:A1; XT3:A1; XT4:A1    |

**Режимы работы регистров:**

| № КВВ                | Сигнал на входе | Режим работы регистра                     |
| -------------------- | --------------- | ----------------------------------------- |
| КВВ1, КВВ3, …, КВВ11 | «Общий»         | Вход в РгА с КВВ нет блокир. сравнения    |
|                      | «ТИ1»           | Вход в РгА с КВВ с блокир. сравнения      |
|                      | «ТИ2»           | Выход из РгА на КВВ нет блокир. сравнения |
|                      | «+5в»           | Выход из РгА на КВВ с блокир. сравнения   |
| КВВ2, КВВ4, …, КВВ12 | «Общий»         | Вход в РгВ с КВВ                          |
|                      | «ТИ2»           | Выход из РгВ на КВВ                       |

**Сигнал «Строб КВВ»** разрешает передачу информации на (из) регистра. Если высокий сигнал на контакте строб, то канал подключён к соответствующему регистру; если низкий — связь между ними разорвана. Сигнал строб может быть постоянным или импульсным.
